🧠 Self-RAG Flow Pipeline

State Machine
1. Adaptive Retrieval [decide_retrieval]
2. Candidate Fetch [retrieve (d₁, d₂, d₃)]
3. Relevance Filter [is_relevant]
4. Draft Generation [generate_from_context]
5. Grounding Check & Fix [is_sup ➔ revise_answer]
6. Utility Check & Rewrite [is_use ➔ rewrite_question]
7. Final Acceptance [accept_answer ➔ __end__]

🛡️ CRAG Flow Pipeline

Tri-Branch DAG
1. Vector DB Search [Initial Retrieval]
2. Confidence Scoring [Retrieval Evaluator]
3a. If Score ≥ Upper [Knowledge Refinement]
3b. If Score ≤ Lower [External Web Search Fallback]
3c. If Lower < Score < Upper [Hybrid Knowledge Fusion]
4. Context Bundling [Clean Prompt Assembly]
5. Generation [Generator LLM ➔ Response]

Full Architectural Feature Matrix

Head-to-head comparison across execution patterns, latency, and failure handling.

Architectural Dimension Self-RAG (Self-Reflective) Corrective RAG (CRAG)
Core Philosophy Internal self-criticism & iterative correction loops. Decoupled evaluation & external knowledge fallback.
Handling Bad/Missing Retrieval Reformulates query (rewrite_question) or aborts. Executes External Web Search (Google / Bing).
Evaluator Role LLM itself evaluates via 4 specialized reflection tokens. Dedicated, lightweight evaluator model scoring confidence.
Document Granularity Chunk-level relevance grading. Sentence-level fine-grained Knowledge Refinement.
Execution Topology Cyclic State Graph (loops on revise & rewrite). Acyclic Directed Graph (DAG) (tri-branch routing).
Latency Profile Variable & higher (multiple LLM inferences per query). Predictable (fast internal, extra latency only on web search).
Air-Gapped / Offline Use ✓ 100% Offline Compatible Requires Web Search API for full corrective power
🧠 When to Choose Self-RAG
  • ✓ Strict Zero-Hallucination Mandates: High-stakes regulatory domains (clinical diagnosis, financial auditing, contract law) where ungrounded claims are unacceptable.
  • ✓ Confidential & Air-Gapped Data: Internal enterprise knowledge bases where queries and documents cannot leave the private VPC to query Google/Bing.
  • ✓ Complex Multi-Turn Reasoning: Queries where initial retrieval often misses nuance and actively benefits from self-directed question rewriting.
🛡️ When to Choose Corrective RAG (CRAG)
  • ✓ Incomplete or Evolving Knowledge Bases: When your internal vector store does not contain all answers and web search fallback prevents "I don't know" responses.
  • ✓ Noisy / Low-Signal Chunks: Large corporate PDFs with boilerplate where sentence-level Knowledge Refinement prevents context pollution.
  • ✓ Public Customer Support & Market Research: Public bots that need to answer questions about competitors, live product updates, and current trends.

⚡ Executive Takeaway

Use Self-RAG if your primary threat is hallucination over private internal documents.
Use Corrective RAG (CRAG) if your primary threat is retrieval failure and knowledge gaps that require automated web fallback.
