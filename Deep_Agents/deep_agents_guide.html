Shallow Agents vs. Deep Agents

Why do standard LLM agents (like basic ReAct or OpenAI Assistant loops) fail when tasks take 30+ minutes or 50+ tool calls?

Dimension Shallow Agent (Naive ReAct) Deep Agent (deepagents Harness)
Execution Horizon Short (1-5 tool iterations). Degradation begins past 10 steps. Long (100+ steps, multi-hour, multi-agent operations).
Task Planning Pure conversational memory; loses intent and "wanders" when side-tracked. TodoListMiddleware: Forces plan drafting (write_todos) and live step-tracking.
Context Window Management Naive message accumulation. Big tool dumps cause instant token overflow or amnesia. Active context offloading: file storage + SummarizationMiddleware + thread history logging.
Subagent Context Isolation Monolithic context. Every sub-task dump floods the parent agent's prompt. Ephemeral subagents via task tool: internal search/code junk is discarded, returning only clean synthesis.
State Checkpoint Growth O(N²) growth — checkpoint files balloon rapidly causing database bottlenecks. DeltaChannel reducer optimizes state writes to O(N).
Tooling Ecosystem Hardcoded Python functions only. Native MCP (Model Context Protocol) client + Anthropic Progressive Skills support.
Security & Guardrails All-or-nothing execution. Risky file edits run uncontrolled. Granular FilesystemPermission rules: allow, deny, or interrupt (HITL).

The Science of Context Offloading in Deep Agents

How Deep Agents solves the context window wall through multi-tier architectural offloading.

1. Ephemeral Subagent Delegation

The task tool mechanism

When a research agent needs to evaluate 40 web links or read 10 huge PDF files, letting the primary agent do this directly poisons its prompt with 100,000+ tokens of raw HTML and citations.

How Deep Agents offloads it: The main agent calls task(subagent_type="web-researcher", prompt="..."). The subagent runs in an isolated, separate context. All intermediate queries and scrapes remain inside the subagent. Only a concise 3-paragraph summary returns to the main agent!

2. Filesystem Artifact Offloading

read_file, write_file, edit_file

Instead of holding large datasets, scraped tables, or source code in the conversational state, the agent writes raw dumps to a virtual filesystem (backed by StateBackend or FilesystemBackend).

How Deep Agents offloads it: The agent uses grep to target exact sections, or calls read_file(offset=100, limit=200) to inspect slices without loading the full 10MB artifact into memory.

3. Automatic Conversation Compaction

SummarizationMiddleware

When token consumption crosses a threshold (e.g., 85% of window size), older turns are compacted by a secondary fast LLM into an ongoing summary.

Where does evicted history go? It is not lost! Deep Agents appends evicted raw turns to /conversation_history/{thread_id}.md on the backend, preserving a complete auditable trail on disk.

4. DeltaChannel Message Reducer

O(N) Checkpoint Scalability

Standard LangGraph agents rewrite the entire conversation message array on every single node invocation, leading to quadratic O(N²) storage explosion in Postgres or SQLite.

How Deep Agents offloads it: DeepAgentState utilizes LangGraph's DeltaChannel with _messages_delta_reducer, storing only state deltas and reducing database serialization overhead to O(N).

The Progressive Disclosure Skills System

Deep Agents natively implements the open Agent Skills Specification (the standard pioneered by Anthropic Claude Code).

What is "Progressive Disclosure"?

If an agent library has 50 specialized domain skills (e.g. Docker deployment, SQL optimization, financial metrics, HIPAA compliance), stuffing all 50 full instruction sets into the system prompt consumes 60,000+ tokens on every single turn before the user even types a word.

Deep Agents Progressive Workflow:
  1. Startup Indexing: The SkillsMiddleware reads only the YAML frontmatter (name and description) from each skill directory.
  2. Compact Prompt: A tiny table of available skill titles and summaries is injected into the system prompt (~200 tokens total).
  3. On-Demand Loading: When the user asks a task matching a skill, the agent dynamically calls read_file(path="/skills/...", limit=1000) to ingest the full SOP and helper code only when needed!

Connecting MCP (Model Context Protocol) Servers

Empower your Deep Agent with hundreds of pre-built tools (PostgreSQL, GitHub, Slack, SQLite, Docker, Brave Search) without writing wrapper code.

How MCP Bridges to Deep Agents

Because Deep Agents is built on top of LangChain and LangGraph, it seamlessly consumes tools generated by langchain-mcp-adapters.

The MultiServerMCPClient connects to multiple servers concurrently over stdio (local CLI binaries) or SSE/HTTP (remote services), discovers their exported tool schemas, and feeds them into create_deep_agent(tools=...).

Quick Installation:
pip install langchain-mcp-adapters deepagents
Deep Agents also supports CLI configuration via .mcp.json for zero-code server attachment in your project root!

mcp_deep_agent.py 
import asyncio
from langchain_mcp_adapters.client import MultiServerMCPClient
from deepagents import create_deep_agent

async def run_mcp_deep_agent():
    # 1. Define your multi-server MCP configuration
    mcp_config = {
        "filesystem": {
            "command": "npx",
            "args": ["-y", "@modelcontextprotocol/server-filesystem", "/Users/sachinmishra/Desktop/Agents_From_Scratch"]
        },
        "github": {
            "command": "npx",
            "args": ["-y", "@modelcontextprotocol/server-github"],
            "env": {"GITHUB_PERSONAL_ACCESS_TOKEN": "ghp_..."}
        },
        "remote_database": {
            "url": "http://localhost:8000/sse",
            "transport": "sse"
        }
    }

    # 2. Connect to the MCP servers asynchronously
    async with MultiServerMCPClient(mcp_config) as client:
        mcp_tools = client.get_tools()
        print(f"Successfully loaded {len(mcp_tools)} MCP tools!")

        # 3. Instantiate the Deep Agent with MCP tools
        agent = create_deep_agent(
            model="google_genai:gemini-2.5-pro",
            tools=mcp_tools,
            system_prompt="You are an automated DevOps and Repository Auditor with direct MCP access.",
            interrupt_on={"github_create_pull_request": True}  # Human approval
        )

        # 4. Invoke agent with full MCP capabilities
        result = await agent.ainvoke({
            "messages": [{"role": "user", "content": "Audit the latest open PR in the repo and check our database logs."}]
        })
        print(result["messages"][-1].content)

from deepagents import create_deep_agent, SubAgent
from deepagents.backends import FilesystemBackend
from deepagents.middleware.summarization import SummarizationMiddleware
from langchain_core.tools import tool

# 1. Custom Tools for Subagents
@tool
def calculate_altman_z_score(
    working_cap: float,
    retained_earnings: float,
    ebit: float,
    mkt_cap: float,
    sales: float,
    total_assets: float,
    total_liabilities: float
) -> str:
    """Calculate Altman Z-Score for bankruptcy risk assessment."""
    z = (
        (1.2 * (working_cap / total_assets)) +
        (1.4 * (retained_earnings / total_assets)) +
        (3.3 * (ebit / total_assets)) +
        (0.6 * (mkt_cap / total_liabilities)) +
        (0.999 * (sales / total_assets))
    )
    zone = "Safe" if z > 2.99 else ("Grey" if z >= 1.81 else "Distress")
    return f"Altman Z-Score: {z:.2f} ({zone} Zone)"

# 2. Declarative Subagents with Context Isolation
quant_subagent: SubAgent = {
    "name": "quant_auditor",
    "description": "Specialized forensic accountant that extracts balance sheet numbers and runs solvency ratios.",
    "system_prompt": "You are a quant auditor. Read filings via read_file and run calculate_altman_z_score. Return only executive bullet summaries.",
    "tools": [calculate_altman_z_score],
    "model": "google_genai:gemini-2.5-pro"
}

# 3. Assemble the Deep Agent Harness
backend = FilesystemBackend(root_dir="/Users/sachinmishra/Desktop/Agents_From_Scratch")

audit_agent = create_deep_agent(
    model="google_genai:gemini-2.5-pro",
    subagents=[quant_subagent],
    skills=["/skills/forensic-accounting/"],
    backend=backend,
    interrupt_on={"write_file": True},  # HITL approval before saving final memo
    system_prompt=(
        "You are DeepAudit, an autonomous forensic due diligence lead. "
        "Always start by using write_todos to map out your investigation. "
        "Delegate raw PDF parsing to quant_auditor to protect conversational context. "
        "Synthesize final findings into /reports/final_due_diligence_memo.md."
    )
)
