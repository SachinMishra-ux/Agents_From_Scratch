Why Supervisor (Subagents-as-Tools) Pattern?
Notice that the User only interacts with the Main Agent. The Hotel sub-Agent and Flight sub-Agent never talk directly to the user—they execute domain tools and return structured results back to the Main Agent.

How the 3 Approval Gates & SQLite Persistence Work

HITL Gate #1

1. Plan Approval

Triggered on find_hotels_subagent after Name, Budget, Source & Destination are captured. User can Approve or Edit before Hotel Finder spins up.

HITL Gate #2

2. Hotel Booking Gate

After Hotel Sub-Agent finds hotels, Main Agent shows options and calls book_hotel_subagent. Pauses before booking for user approval/edit.

HITL Gate #3

3. Flight Booking Gate

Main Agent asks for Flight Dates, runs search_flights_subagent, shows flights, and pauses on book_flight_subagent before booking.

Middleware & Checkpointer Configuration (trip_planner_agent.py) SqliteSaver + HumanInTheLoopMiddleware 
hitl_middleware = HumanInTheLoopMiddleware(
    interrupt_on={
        "find_hotels_subagent": {"allowed_decisions": ["approve", "edit", "reject"]}, # Gate 1: Plan Approval
        "book_hotel_subagent":  {"allowed_decisions": ["approve", "edit", "reject"]}, # Gate 2: Hotel Approval
        "book_flight_subagent": {"allowed_decisions": ["approve", "edit", "reject"]}, # Gate 3: Flight Approval
    }
)
sqlite_checkpointer = SqliteSaver(sqlite3.connect("trip_planner_memory.db", check_same_thread=False))
