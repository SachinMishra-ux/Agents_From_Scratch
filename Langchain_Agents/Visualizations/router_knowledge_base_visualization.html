3 Educational Breakdown: The 3 Core Pillars of the Router Pattern

Everything you need to explain how this code operates under the hood to your students.

1

Dynamic Gating & Query Optimization

The router does NOT just forward the raw query. It uses .with_structured_output(ClassificationResult) to:

  • Filter out irrelevant knowledge bases entirely.
  • Generate customized sub-questions optimized for each source (e.g. asking GitHub for code files, and Slack for chat threads).
2

Dynamic Fan-Out via Send()

Instead of hardcoding static edges, the conditional edge returns: 

[Send(c["source"], {"query": c["query"]}) 
 for c in state["classifications"]]

If 1 source is chosen, 1 agent runs. If 3 are chosen, 3 agents run in parallel in a single superstep!

3

State Reducer (operator.add)

In parallel graphs, if 3 nodes return values to the same key, standard state overwrites them.

results: Annotated[list, operator.add]

operator.add acts as an automatic gather/collector: it appends all outputs into a single list before the Synthesizer runs.

When to Choose the Router Pattern vs. Other Agentic Patterns
Pattern Who Controls Routing? Execution Style Best Use Case
Router (Notebook 10) Upfront Classifier Node Split → Parallel Execute → Synthesize Multi-source knowledge bases (Docs, Code, Chats)
Subagents (Notebook 4 / 9) Main Supervisor as a Tool Caller Hierarchical Hub-and-Spoke Personal assistant, deep research, code execution
Handoffs (Notebook 8 / 9 Swarm) Specialist Agents via Command(goto=...) Decentralized Peer-to-Peer Mesh Customer support triage, multi-turn loan underwriting
Map-Reduce (Notebook 6 / 7) Python loop / Graph State Reducers Batch Fan-out across $N$ identical items Analyzing 10 competitors, indexing 50 documents
